# AI Narrative — Implementation Reference

## Overview

The AI narrative is a 1–2 sentence plain-language summary generated per coin on demand. It interprets the coin's current chatter level, tone shift, spot volume, funding rate, open interest, and whale positioning into a concise analyst-voiced observation. It is generated by OpenAI and cached at two layers to avoid redundant calls.

---

## Architecture

```
Browser
  │
  ├─ Layer 1: in-memory JS cache (narrativeCache{})
  │    Key: coin symbol  →  expires when pushedAt changes
  │
  └─ fetch POST /api/coin-narrative  (only on cache miss)
       │
       ├─ Layer 2: Cloudflare KV (NARRATIVE_CACHE namespace)
       │    Key: "{SYMBOL}:{pushed_at}"  →  expires on next feed cycle
       │    TTL: 2 hours (safety net)
       │
       └─ OpenAI API  (only on KV miss — once per coin per feed cycle)
            Model: gpt-5.4-nano
            max_completion_tokens: 120
            temperature: 0.35
```

The cache key includes `pushed_at` (the feed timestamp) rather than a TTL timer. This means the narrative is tied to the data it was generated from — it auto-invalidates when the feed updates, not on an arbitrary clock.

---

## API Endpoint

**Route:** `POST /api/coin-narrative`
**File:** `src/pages/api/coin-narrative.ts`
**Infrastructure:** Astro SSR route running as a Cloudflare Pages Function

### Request

```json
{
  "symbol": "BTC",
  "pushedAt": "2026-03-29T04:00:00.000Z",
  "coinData": {
    "chatter": {
      "ok": true,
      "level": "Buzzing",
      "tone_shift": 4,
      "tone_baseline": 12,
      "distinct_authors": 318
    },
    "volume": {
      "ok": true,
      "label": "Very High",
      "usd_fmt": "$38.2B"
    },
    "futures": {
      "ok": true,
      "funding_label": "Elevated",
      "funding_rate": "0.0312%",
      "oi_label": "High",
      "oi_usd_fmt": "$14.1B",
      "whale_label": "Long-skewed",
      "whale_pct": 68
    }
  }
}
```

- `symbol` — coin ticker, max 20 chars, uppercased server-side
- `pushedAt` — the `pushed_at` timestamp from the payload; used as the cache key component. If omitted, KV caching is skipped but the call still proceeds.
- `coinData` — the raw coin object from the feed. Only fields with `ok: true` are included in the prompt.

### Response

- **200** — plain text narrative string (`Content-Type: text/plain; charset=utf-8`)
- **400** — invalid/missing request body
- **429** — forwarded from OpenAI rate limit
- **500** — OpenAI error or server misconfiguration
- **502** — OpenAI returned an empty response

Response headers include `X-Narrative-Cache: hit` or `X-Narrative-Cache: miss` for observability.

### CORS

The endpoint reflects the request `Origin` header back if it matches an allowlist. No credentials are involved, so this is safe.

**Allowed origins:**
- `https://pulse.instrumetriq.com`
- `https://instrumetriq.com`
- Any `chrome-extension://` origin
- Any `moz-extension://` origin (Firefox)

A preflight `OPTIONS` handler returns 204 with the appropriate `Access-Control-Allow-*` headers.

```
Access-Control-Allow-Origin: <reflected origin>
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

## The Prompt

The prompt is built dynamically from whatever data fields are present and valid (`ok: true`). Fields with `ok: false` are silently omitted so the model never sees placeholder or error state values.

```
You are a crypto data analyst writing a brief summary for a public sentiment monitoring page.

Data for BTC:
Chatter level: Buzzing (vs this coin's 30-day baseline)
Tone shift: +4 points above its historical baseline
30-day tone baseline: 12
Distinct X authors this cycle: 318
24h spot volume: Very High · $38.2B
Funding: Elevated · 0.0312% / 8h
Open interest: High · $14.1B
Whale positioning: Long-skewed (68% long / 32% short)

Write exactly 1-2 sentences summarizing what this data signals about current market activity. Rules:
- Be specific — use the actual numbers from the data above
- Never use the words "bullish" or "bearish"
- No trading advice or price predictions
- Analyst voice, not marketer voice
- Maximum 55 words
```

**Model parameters:**
- Model: `gpt-5.4-nano` (GPT-5 family requires `max_completion_tokens`, not `max_tokens`)
- `max_completion_tokens`: 120 (generous ceiling; prompt enforces 55-word limit)
- `temperature`: 0.35 (low enough for consistency, enough for natural variation)
- `stream`: false

## Cloudflare KV Cache

**Namespace:** `NARRATIVE_CACHE`
**Binding declared in:** `wrangler.toml`
**Namespace ID:** `57c225291aff4daba57e04e679064f57`

```toml
[[kv_namespaces]]
binding = "NARRATIVE_CACHE"
id = "57c225291aff4daba57e04e679064f57"
```

**Cache key format:** `{SYMBOL}:{pushed_at}` — e.g. `BTC:2026-03-29T04:00:00.000Z`

**Cache read:** happens before the prompt is built or OpenAI is called. On hit, the stored string is returned immediately.

**Cache write:** fire-and-forget after a successful OpenAI response. Uses `.catch(() => {})` so a KV write failure never blocks the response. TTL is set to 7200 seconds (2 hours) as a safety net, but in practice the key changes with every feed push (~10 minutes), so old keys naturally fall out of use.

**Accessed via:** `locals.runtime.env.NARRATIVE_CACHE` (Cloudflare Workers runtime binding pattern). If the binding is absent (e.g. local dev without the namespace configured), caching is silently skipped and the endpoint still functions normally.

## Frontend Integration (Pulse Page)

**File:** `src/pages/pulse/index.astro`

### In-memory cache

```js
const narrativeCache: Record<string, string> = {};
let pushedAt = '';
```

Before any network call, the frontend checks `narrativeCache[symbol]`. On a hit, the stored text is rendered immediately — no fetch, no KV lookup, no OpenAI call.

### Fetch call

```js
const res = await fetch('https://instrumetriq.com/api/coin-narrative', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ symbol, coinData: coin, pushedAt }),
});
```

The absolute URL is required because the pulse page is served from `pulse.instrumetriq.com` (a subdomain), while the API lives on `instrumetriq.com`. A relative URL would resolve to the wrong origin.

### Cache invalidation

When the feed polling loop detects a new `pushed_at`, the in-memory cache is cleared:

```js
if (pushedAt && pushedAt !== data.pushed_at) {
  Object.keys(narrativeCache).forEach(k => delete narrativeCache[k]);
}
pushedAt = data.pushed_at;
```

This forces a fresh fetch on the next coin view after a feed refresh. That fresh fetch will hit the KV cache (populated by the first user to view that coin after the update) rather than calling OpenAI again.

### UI states

| State | Element | Behaviour |
|---|---|---|
| Loading | `.vw-narrative-loading` | "Analyzing..." in muted italic |
| Loaded | `.vw-narrative-text` | Plain text, 13px, muted colour, top border |
| Error / empty | — | Element is cleared silently, no error shown to user |

The narrative container is always rendered into the detail panel DOM on coin selection. `fetchNarrative()` is called immediately after and updates the container asynchronously.

## Extension Implementation

**Implemented in:** `extension/popup.js` (v1.0.6)

### State

```js
// In-memory cache. Key: coin symbol. Cleared on feed cycle advance.
const narrativeCache = {};
let narrativePushedAt = null;
```

### Trigger

`fetchNarrative(sym, coinData)` is called from `showCard()` each time the user navigates to a coin. This means the fetch is always lazy - it happens when the user actually looks at a coin, never during background polling.

```js
// Inside showCard():
if (sym && currentPayload?.coins) {
  const coinData = currentPayload.coins.find(c => c.symbol === sym);
  if (coinData) fetchNarrative(sym, coinData);
}
```

### Cache check and fetch

```js
async function fetchNarrative(sym, coinData) {
  const pushedAt = currentPayload?.pushed_at ?? null;
  const el = cardAreaEl.querySelector('.narrative-area[data-symbol="' + sym + '"]');
  if (!el) return;

  // In-memory cache hit - render immediately, no network call
  if (narrativeCache[sym]) {
    el.innerHTML = '<span class="narrative-text">' + esc(narrativeCache[sym]) + '</span>';
    return;
  }

  el.innerHTML = '<span class="narrative-loading">Analyzing...</span>';

  // Only include data sections that passed their quality gate
  const cd = {};
  if (coinData.chatter?.ok) cd.chatter = coinData.chatter;
  if (coinData.volume?.ok)  cd.volume  = coinData.volume;
  if (coinData.futures?.ok) cd.futures = coinData.futures;

  try {
    const res = await fetch('https://instrumetriq.com/api/coin-narrative', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ symbol: sym, pushedAt, coinData: cd })
    });
    if (!res.ok) { el.innerHTML = ''; return; }
    const text = (await res.text()).trim();
    if (!text) { el.innerHTML = ''; return; }
    narrativeCache[sym] = text;
    // Re-check the element is still in DOM (user may have navigated away)
    const live = cardAreaEl.querySelector('.narrative-area[data-symbol="' + sym + '"]');
    if (live) live.innerHTML = '<span class="narrative-text">' + esc(text) + '</span>';
  } catch (_) {
    // Silent failure - narrative is an enhancement, not core data
    el.innerHTML = '';
  }
}
```

### Cache invalidation

In `storage.onChanged`, when a new payload arrives, `pushed_at` is compared against `narrativePushedAt`. If it has advanced (new feed cycle), the entire in-memory cache is wiped before the new payload is stored:

```js
if (newPayload?.pushed_at && newPayload.pushed_at !== narrativePushedAt) {
  Object.keys(narrativeCache).forEach(k => delete narrativeCache[k]);
  narrativePushedAt = newPayload.pushed_at;
}
```

This matches the pulse page pattern exactly. The next coin navigation after a feed update will always trigger a fresh fetch, which hits the KV cache rather than calling OpenAI again.

### DOM container

Every card rendered by `buildCardHtml()` includes a `.narrative-area` container with a `data-symbol` attribute:

```html
<div class="narrative-area" data-symbol="BTC"></div>
```

The container sits between the whale lean row and the disclaimer line. `fetchNarrative` targets it by `data-symbol` so that navigation races (user moves away before fetch resolves) are handled safely - the stale element is simply not updated.

### UI states

| State | Element | Behaviour |
|---|---|---|
| Loading | `.narrative-loading` | "Analyzing..." in muted italic |
| Loaded | `.narrative-text` | Plain text, 12px, muted colour, top border via `.narrative-area` |
| Error / empty | - | Container is cleared silently, no error shown to user |

### Cost profile

`gpt-5.4-nano` at 120 output tokens is extremely cheap. With the two-layer cache in place, cost scales with the number of distinct coins viewed per feed cycle across all users - not with popup opens or refreshes. At current traffic this is negligible.
